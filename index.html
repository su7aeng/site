AI 활용 방식

자료 조사를 비롯해 반복 업무를 줄이는 사내 도구 제작에 AI를 활용하고 있습니다. 개발자의 업무를 대체하는 것이 아닌, 복잡하지 않은 범위 내에서 보안 원칙을 지켜 활용합니다.

자료 조사
  1. 1
    질문 정의의사결정 사항 및 필요 근거 정리
  2. 2
    수집공식 문서, 공개 통계, 경쟁 서비스, 검색 트렌드 등을 AI를 활용해 수집
  3. 3
    검증원문 확인 및 수치는 2개 이상 출처로 교차 검증
  4. 4
    정리표, 장표로 정리 후 결론 및 다음 액션 도출

생산성 높이기

서비스 개발이 아닌, 반복 업무를 줄이는 사내 도구를 만들어 팀의 생산성을 높이고 AI 활용 역량을 키워 왔습니다.

1. 정의해결할 문제와 측정 지표 정의
2. 구현AI를 활용해 코드, 문서 초안 작성
3. 사내 연동내부 서버 및 사내 시스템 연동
4. 확인지표로 효과 검증 후 개선
원칙
  • 사내 도구, 데이터 정리, 리포트 등 복잡하지 않은 범위까지만 직접 구현
  • 서비스 핵심 기능 및 운영 시스템은 개발팀, 외주 개발사가 담당하며 요구사항과 스펙 정의로 협업
  • 공식 공개 API 및 오픈소스 범위 내에서만 개발
  • 인증 키와 원본 데이터는 내부 서버에만 보관
  • 권한이 있는 인원만 접근 가능하도록 제한

문제 상황

매출(Cafe24)과 행동 데이터(GA4)가 분리되어 한 화면에서 성과 판단 불가. 메인 진열 슬롯별 성과 파악이 어렵고, 일일 매출은 수기로 집계.

문제 정의

지표 자체의 신뢰도가 낮음.

  • 제휴 광고 유입과 해외 봇 트래픽(평균 체류 약 2초)이 섞여 전환율 및 퍼널 왜곡
  • 구매하기, 장바구니 버튼 구조 변경으로 기존 퍼널 정의와 불일치
해결 과정
  • Cafe24 API와 GA4를 연동한 AARRR 통합 대시보드 구축
  • 아트 61개, 라이프 60개 진열 슬롯 매핑으로 슬롯 단위 클릭 및 매출 추적
  • 광고 유입 분리, 봇 트래픽 플래그 처리 및 변경된 버튼 구조에 맞춘 퍼널 재정의
  • GMV, 매출총액, TOP 5, 목표 달성률 리포트 내부 서버에서 매일 자동 발송
  • 개발팀 리소스 투입 없이 AI를 활용해 API 연동 구현 및 내부 서버 연동
결과
  • 의사결정권자와 운영, MD 담당자가 동일한 데이터로 매일 성과 확인
  • 통합 데이터를 통해 손익 구조 문제 및 알림 과다로 인한 회원 탈퇴 급증 발견
  • 탐색 확장(랭킹, 신상, 트렌딩)을 우선 과제로 선정하는 근거로 활용
배운 것

대시보드 구축보다 지표 정의가 우선되어야 하며, 데이터 오염 요인을 먼저 제거해야 의사결정에 활용할 수 있다는 점을 배웠습니다.
